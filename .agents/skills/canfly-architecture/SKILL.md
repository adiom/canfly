# Canfly — архитектура (актуально на 2026-11-10)

Прежде всего прочитай корневой `AGENTS.md`; он имеет приоритет над этим навыком. Сверяй утверждения ниже с текущим кодом, а не со старым аудитом. Для Next.js используй установленную документацию в `node_modules/next/dist/docs/`.

## Предметная модель

- **Release** — единая публичная медиасущность/произведение, НЕ тип носителя. Релиз включает издания любых поддерживаемых форматов, включая текстовые (глава не обязательна для форматов `digital` и `artwork`). Не назначай `work_type` релизу и не своди релиз к «одной книге».
- `releases → editions → chapters` — существующая структура публикации. Фактические колонки и связи сверяй со схемой целевого окружения, SQL и репозиториями. `is_primary` не доказывает литературный канон.
- `series`, `characters`, `release_characters`, `places`, `games`, пользовательские состояния — связанные подсистемы, а не замена основной модели.
- Канон произведений утверждает автор; seed-данные, старые паспорта и догадки AI не считаются подтверждением. Не меняй произведения/источники ради технического теста.

## Инварианты

1. Не создавай дублирующие модели контента, API или хранилища поверх существующих.
2. SQL централизован в серверных репозиториях; клиентские компоненты не получают прямого доступа к БД.
3. `proxy.ts` обслуживает часть legacy-путей и проверок; не восстанавливай retired API/роуты.
4. Для изменений, зависящих от БД, сверяй фактическую схему и [известные расхождения PostgreSQL](../../../docs/architecture/postgresql-schema-drift.md). Инвентаризацию миграций веди по [canfly-data-access](../canfly-data-access/SKILL.md).
5. AI-чат: `manual/hybrid` не дают автоматической генерации; `blocked/disabled` запрещают вызов модели. Подтверждённый текст ответа берётся из сохранённого хода, а не из EOF потока.
6. Канон Сони в коде оставлен как черновик. Не активируй его автоматически.
7. Не трогай незакоммиченные изменения других задач. Перед задачей и после — `git status --short`.

## Как работать экономно

Сначала найди существующий маршрут и 1–2 ближайших модуля, затем прочитай только нужные части. `docs/UPDATES.md` — журнал, а не источник истины. Для подробного состояния AI-чатов могут быть локальные отчёты в `C:\canfly\2026\chatgpt\`, но всегда сверяй их с Git и кодом.
