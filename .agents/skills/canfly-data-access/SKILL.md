# Canfly — доступ к данным

Изучи корневой `AGENTS.md` и фактическую схему/код перед правкой. Подключение через `pg`, без ORM. `lib/db.ts` содержит `getPool`, `dbQuery`, `dbQueryOne`, `dbUpdatePartial`, `withTransaction`.

## Правила

- Все пользовательские значения передавай параметрами `$1`, `$2`; динамические имена объектов — только из фиксированного whitelist.
- SQL помещай в `lib/server/`; не в React-компоненты, страницы или публичные клиентские модули.
- При частичном обновлении различай отсутствие ключа/`undefined` и явный `null`: не обнуляй незатронутые поля Studio, паспорта, контент или метаданные.
- Связанные записи — через `withTransaction(client => ...)` и `client.query`, с единым порядком блокировок.
- Для хода AI-чата изучи `claimCharacterTurn`, `completeCharacterTurn`, `failCharacterTurn`, `fetchCharacterTurnSnapshot` в `lib/server/users.ts` и `turn-status.ts`. `requestId` обозначает логический вопрос, `attemptId` — конкретную попытку; повтор проверяется под блокировкой, но **строгого exactly-once в БД нет**.
- Статус `pending` с истекшим TTL нельзя считать безопасным для повторного платного вызова: результат может быть неизвестен. Нельзя терять подтверждение записи ответа.
- Канонические источники чата только читаются; реплики читателя и выводы AI не записываются в литературный канон.

## Миграции и среда

- Перед проектированием миграции инвентаризируй SQL-файлы, включая вложенные, известную историю применения и схему целевой БД. Наличие SQL-файла подтверждает только изменение в репозитории.
- [Аудит PostgreSQL от 19.11.2026](../../../docs/architecture/postgresql-schema-drift.md) фиксирует расхождения между production, test и `postgres/schema.sql`. Если фактическая схема неизвестна, отложи зависящие от неё изменения и укажи, что нужно подтвердить.
- Если изолированной тестовой БД нет, запрещены миграции, глобальный setup, тестовые INSERT/UPDATE/DELETE и команды, чьи побочные эффекты не проверены. Для записи в рабочую БД нужны отдельное разрешение, проверка цели и резервная копия.
- `pnpm db:structure` и даже сборка с prerender могут обращаться к подключённой БД: сначала оцени побочные эффекты. Не печатай `.env*`, URL, ключи, личные данные.
- Изменения схемы сопровождай обновлением типов, Zod и узкими тестами. Не редактируй уже применённую миграцию.

## Проверка

Сначала unit-тесты без БД: `npx --no-install playwright test -c playwright.unit.config.ts` или `pnpm test:unit` при рабочем pnpm. DB-e2e — только в изолированном окружении. Не выдавай mock-SQL тест за проверку настоящей транзакции.
