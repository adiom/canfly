# ADR 0001: Публичные маршруты, серверная логика и доступ к БД

- Status: accepted (описание уже существующего устройства, не новое изменение)
- Evidence: код на [`a2dd068e00cb54f9dcd2a40b75ba04f7a420e65b`](https://github.com/adiom/canfly/tree/a2dd068e00cb54f9dcd2a40b75ba04f7a420e65b)

## Context

UI, обработчики API и формы работают с общей PostgreSQL-схемой. Права доступа нельзя выводить из одного только клиентского интерфейса.

## Decision

Текущее устройство: маршруты в [`app/`](../../../app/), Server Actions в [`lib/actions/`](../../../lib/actions/), доменные запросы в [`lib/server/`](../../../lib/server/), соединение через [`lib/db.ts`](../../../lib/db.ts). [`proxy.ts`](../../../proxy.ts) даёт ранний редирект; [`studio-auth.ts`](../../../lib/server/studio-auth.ts) проверяет владение объектом в серверных операциях.

## Consequences

Новая функция должна явно указать маршрут, серверную проверку доступа, SQL-модуль и таблицы. Этот ADR документирует проверенное состояние, не утверждает, что все существующие обработчики уже полностью ему соответствуют. Изменение модели фиксируйте новым ADR.
