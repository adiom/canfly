# ExecPlan — защита сохранения глав, этап 1

Исходная версия — `0c65844efe80de4b437e1f98603dece589df71ca`. Рабочее дерево было чистым. Каталог одноразовой PostgreSQL 17.12 до миграции совпал с репозиторным baseline.

## Проход 1

1. Воспроизвести полный снимок при смене заголовка, принятие пустого заголовка, конкуренцию записей и позднее сохранение удалённой главы. Новые unit-тесты очереди и валидации упали на исходном коде.
2. Передавать патч от последнего подтверждённого снимка. Существующие потребители очереди по-прежнему получают полный снимок первым аргументом. Восстановление выполняется после очистки очереди и обновляет её базу вместе с редактором.
3. Проверять `expectedRevision` под блокировкой строки до записи и архивации. Триггер продвигает ревизию и для старых путей записи. Studio требует ревизию, MCP принимает её как необязательный параметр для совместимости.

## Проверка и откат

Проверить unit-тесты, DB-контракты, повторный запуск миграции и браузерные сценарии с двумя вкладками, историей и удалением. В CI точная сверка baseline предшествует миграции, затем тесты приложения выполняются на мигрированной схеме.

Подтверждены 218 unit-тестов, 12 DB-тестов и 7 проверок через Playwright, включая 3 браузерных сценария. Повторное применение миграций не нашло ожидающих версий, проверка журнала прошла.

Для развёртывания схема должна опережать код. При откате приложения добавленная колонка и триггер совместимы с предыдущей версией. Удаление схемы потребует отдельной миграции после проверки потребителей.

## Проход 2 — замечания ревью de26bad

- Воспроизвести потерю черновика после конфликта и блокировку сохранения текста пустым заголовком. При конфликте отделить архив от активного черновика. Автор может просмотреть, скопировать, восстановить или удалить снимок. Восстановление отправляет только текст с ревизией текущей главы, архивная копия остаётся до удаления.
- Привязать новые активные и архивные черновики к автору и главе. Старый ключ без автора переносится в архив для ручного восстановления. Предпочитать `localStorage` для архива и сохранять исходную запись при недоступности обоих хранилищ.
- При пустом заголовке сохранять только корректный текст. Подтверждённый текст убрать из ожидающего патча, пустое поле оставить локально и отобразить ошибку.
- Для `test:db` до фикстур проверить фактическую локальную PostgreSQL 17, колонку ревизии и включённый триггер. Каталог читать под тестовой ролью в режиме read-only. Журнал и точный baseline по-прежнему проверяются отдельными командами миграций.

Две браузерные регрессии воспроизведены на `de26bad`. После исправления прошли 219 unit-тестов, 12 DB-тестов под тестовой ролью приложения и 11 проверок Playwright, из них 7 в Chromium. Preflight ожидаемо завершил `test:db` кодом 1 до фикстур при отсутствии миграции и при URL вне loopback.

### Предложение по MCP для отдельного согласования

1. После согласования опубликовать версионированные варианты update и restore с обязательным `expected_revision`, оставив существующие инструменты на переходный период. Клиент получает ревизию вместе со снимком главы и передаёт её при записи. Измерять использование старого пути без записи содержимого главы в журналы.
2. Перевести клиентов и назначить срок отключения записи без ревизии. После отключения отклонять отсутствующую ревизию с подсказкой перечитать главу. Запрос со старой ревизией должен проигрывать до записи и создания версии. Подставлять актуальную ревизию на сервере для старого запроса нельзя, поскольку тогда он снова сможет молча перезаписать свежий текст.

До согласования действующий MCP-контракт сохраняется. Вызовы без ревизии по-прежнему могут перезаписать актуальные данные.
