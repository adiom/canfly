# Canfly — доступ, безопасность, побочные эффекты

Читай `AGENTS.md` и существующие guards перед изменением. Любое расширение прав или доступ к production — отдельное решение, не побочный эффект фичи.

## HTTP и права

- Первичная маршрутизация/некоторые проверки в `proxy.ts` (Next.js 16), а не `middleware.ts`; обязательно сверяй matcher. Проверка в proxy **не заменяет** server-side authorization.
- Studio: `lib/server/studio-auth.ts`, операции с релизами/изданиями/главами требуют соответствующего `require*Ownership()`. Проверяй IDOR для каждого ID, поступающего с клиента.
- Валидация Zod в actions/API; обработчики следуют `apiHandler()`, rate limit — `lib/server/rate-limit.ts`. Не возвращай внутренние ошибки или закрытые поля.
- Персонажи: публичный DTO не включает `system_role`, `passport`, закрытую metadata, а роли `system` не видны читателю.
- AI-чат: `blocked`, `disabled`, `manual`, `hybrid` и отсутствие `character_ai_settings` применяет documented defaults, а пустой `system_role` блокирует модель. Не увеличивай расход на повтор при неизвестном статусе. Статус ответа подтверждается по `requestId` и сохранённой записи, не по завершению потока.
- Манифест канона публикуется только после авторского утверждения; запрет спойлеров автора сильнее просьбы читателя.

## Входящие файлы, HTML и браузер

- Серверная очистка HTML через существующий `lib/sanitize.ts` до сохранения; не доверяй MIME/расширению файла без сигнатуры и лимита.
- Сохраняй CSP/HSTS и ограничения iframe из `next.config.mjs`; точечные исключения не расширяй на весь сайт.
- Legacy/retired маршруты не возвращай к жизни без решения.

## MCP и внешние доступы

- `/api/mcp` ограничен администратором; OAuth и токены проверяй по действующему коду `lib/server/mcp-oauth.ts`. Не создавай delete/записывающие тулы без явного задания и оценки прав.
- Не предполагай, что `.mcp.json` существует и MCP подключён: проверяй текущие файлы/доступные инструменты. На 10.11.2026 проектного `.mcp.json` в рабочем дереве не было.
- Не печатай секреты `.env*`, токены или URL подключения. Не меняй Cloudflare/Vercel/Neon/производственную БД без явной команды.
- Перед запуском dev/e2e/build проверь, не пишет ли команда в рабочие данные. Тестовая БД должна быть подтверждена, а не предположена.

## Завершение

Минимальная правка → узкие безопасные тесты → lint/typecheck → build при безопасной среде → отчёт о непротестированном. Сверяй `git status --short`; не делай `git reset --hard`, `clean`, `push`, миграцию или деплой как «уборку» без разрешения.
