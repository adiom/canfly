# Архитектурные решения (ADR)

ADR фиксирует решение, причины, альтернативы и последствия. Статусы: `proposed`, `accepted`, `superseded`. Черновик не следует трактовать как реализованную функциональность.

Шаблон: `NNNN-короткое-имя.md` с полями `Status`, `Context`, `Decision`, `Consequences`, `Evidence` (ссылки на код и проверенный SHA). Не переписывайте принятое решение задним числом: новый ADR указывает, какой заменяет. Для решений о схеме БД отдельно фиксируйте порядок внедрения, обратную совместимость и план восстановления.

Первый зафиксированный факт: [0001 — разделение публичной модели и серверного доступа](0001-app-router-data-access.md).
